# 04：阶段 A 实战与闭卷验收

## 本课目标

在不照抄前三课步骤的情况下，独立写出任务说明、主导一次低风险真实改动，并用当前状态、diff、测试和风险说明证明结果。

## 任务说明

在 `G:\learn_asr` 中完成一次低风险、真实、有证据的改进。可选方向：

- 修复一处已证实失效的文档导航；
- 补充一个缺失但可实际运行的最小命令示例；
- 修正一处文档与当前代码不一致的描述；
- 为一个简单纯函数补充边界测试并修复已复现的问题。

不要选择模型重训、批量重构、依赖大升级或部署变更。

## 闭卷规则

先自己写提示词，再回看前 3 课。提示词必须覆盖 GCCD，但不要求使用固定格式。

Codex 开始工作后，你可以回答必要问题，但不能只说“你看着办”。至少做一次基于证据的反馈，例如指出缺少某项验证，或确认某项风险可以接受。

## 必须提交的证据

把以下内容记录到 [学习记录](学习记录.md)：

1. 原始任务说明；
2. 修改前的事实或复现；
3. Codex 改了哪些文件；
4. 验证命令和结果；
5. 你如何审查 diff；
6. 未验证的范围；
7. 如果重做，你会怎样改进提示词。

## 本课验收与评分表

每项 0–2 分：

| 项目 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 目标 | 模糊 | 大致可懂 | 可观察且范围明确 |
| 上下文 | 无 | 给了文件或现象 | 有证据、入口和复现 |
| 约束 | 无 | 有笼统限制 | 对范围、工程、安全均适当 |
| 完成标准 | 无 | 只说“测试通过” | 与需求直接对应且可执行 |
| 调查 | 直接改 | 简单查看 | 建立当前状态证据 |
| 修改 | 无关或过大 | 基本满足 | 范围恰当且符合项目风格 |
| 验证 | 没运行 | 单一间接检查 | 针对性检查并说明覆盖范围 |
| 审查 | 没看 diff | 只看文件列表 | 检查意外改动和风险 |
| 汇报 | 只说完成 | 有摘要 | 结果、证据、风险清楚 |
| 主导权 | 完全放任 | 偶尔反馈 | 能基于证据纠偏 |

总分 20。达到 16 分且“验证”“审查”均不是 0 分，阶段 A 通过。未通过时只重做薄弱部分，不必机械重来全部任务。
